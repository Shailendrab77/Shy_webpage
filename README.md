# WhatsApp Payout Request Agent

Production-oriented **Node.js + TypeScript** service that accepts payout requests over **WhatsApp Cloud API**, uses an **LLM only for structured understanding**, and writes records to **Google Sheets** through deterministic backend code.

## What this application does

Customers send natural-language messages such as:

- `I want a payout of 5000`
- `What's the status of PAY-10001?`
- `Cancel my payout request PAY-10001`

The system:

1. Receives the WhatsApp webhook
2. Extracts intent/fields via a validated LLM (or heuristic fallback)
3. Validates customer, amount, duplicates, and ownership in backend code
4. Creates a `Pending` payout request in Google Sheets
5. Returns a unique request code such as `PAY-10001`

**Safety rule:** the AI never writes to Google Sheets and never approves payouts. Status starts as `Pending` unless backend/admin code changes it.

## Architecture

```
Customer → WhatsApp → Webhook → Conversation Orchestrator
                                      │
                                      ├─ AI Agent (structured JSON only)
                                      ├─ PayoutService / Validator (deterministic)
                                      ├─ CustomerRepository / PayoutRepository
                                      │     └─ Google Sheets (swappable)
                                      └─ WhatsAppService → reply
```

### Design for future migration

Repositories are interface-based:

- `CustomerRepository`
- `PayoutRepository`
- `ConversationStore`
- `IdempotencyStore`

Today: Google Sheets + in-memory state.  
Later: PostgreSQL / MySQL / Redis / real payout API without rewriting WhatsApp conversation logic.

## Google Cloud + Sheets setup

1. Create a Google Cloud project.
2. Enable the **Google Sheets API**.
3. Create a **service account** and download its JSON key (or copy email + private key).
4. Create a spreadsheet with tabs `Customers` and `PayoutRequests` (see `docs/google-sheets-template.md`).
5. Share the spreadsheet with the service-account email (**Editor**).
6. Put the spreadsheet ID and credentials into `.env`:

```env
GOOGLE_SHEETS_SPREADSHEET_ID=your_spreadsheet_id
GOOGLE_SERVICE_ACCOUNT_EMAIL=your-sa@project.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
```

Or:

```env
GOOGLE_APPLICATION_CREDENTIALS=./credentials/service-account.json
```

Never commit credentials. `credentials/`, `*.json` service-account files, and `.env` are gitignored.

### Concurrency note

Request codes are generated by reading the latest `PAY-N` value and appending the next number. Google Sheets is **not transactional**. Under concurrent writes, collisions are mitigated with a uniqueness check + retry, but high volume should move code generation to a DB sequence.

## WhatsApp Cloud API setup

1. Create a Meta developer app and add **WhatsApp**.
2. Create/select a WhatsApp Business phone number.
3. Generate a permanent access token for the phone number.
4. Set a verify token of your choosing.
5. Configure env vars:

```env
WHATSAPP_ACCESS_TOKEN=...
WHATSAPP_PHONE_NUMBER_ID=...
WHATSAPP_VERIFY_TOKEN=your-verify-token
WHATSAPP_API_VERSION=v21.0
```

6. Point the webhook callback URL to:

```text
https://<your-public-host>/webhook
```

Subscribe to the `messages` field.

### Local webhook testing

Use a tunnel (ngrok, Cloudflare Tunnel, etc.):

```bash
npm run dev
# then expose http://localhost:3000/webhook
```

Verification uses `GET /webhook` with Meta's `hub.challenge` flow.

You can also POST a sample payload:

```bash
curl -X POST http://localhost:3000/webhook \
  -H 'Content-Type: application/json' \
  -d '{
    "object":"whatsapp_business_account",
    "entry":[{"changes":[{"value":{"messages":[{"from":"919876543210","id":"wamid.local.1","timestamp":"1","type":"text","text":{"body":"I want a payout of 5000"}}]}}]}]
  }'
```

Without Sheets credentials, the app falls back to an in-memory demo customer (`CUST001` / `919876543210`) in non-production mode.

## Security

- Secrets only via environment variables
- Webhook verify token check
- Zod validation for LLM output and webhook payloads
- Rate limiting on webhook and admin routes
- Helmet + limited CORS
- Admin API key gate
- Customer ID + WhatsApp ownership checks before returning status/cancel
- Structured logging with redaction; no tokens/credentials in logs
- Idempotency on WhatsApp `message.id` to prevent duplicate payouts on retries

## Idempotency & duplicate protection

1. **Message ID store** — repeated webhook deliveries with the same WhatsApp message ID reuse the previous reply and do not create another payout.
2. **Source message ID on payout rows** — repository-level guard if Sheets includes the column.
3. **Recent duplicate window** — same customer + same amount + `Pending` within `DUPLICATE_REQUEST_WINDOW_MINUTES` is blocked.

If WhatsApp send fails after creation, retries will not create a second request.

## Deploy

1. Build: `npm run build`
2. Run: `node dist/server.js` (or `npm start`)
3. Provide production env vars via your secret manager
4. Put TLS termination and the public webhook URL in front of the service
5. Ensure the service account can edit the spreadsheet
6. Prefer a process manager (systemd, PM2, Kubernetes, Cloud Run)

Recommended production hardening:

- Move conversation + idempotency stores to Redis
- Move payout storage to PostgreSQL
- Queue webhook processing for higher throughput
- Rotate WhatsApp and Google credentials regularly

## Migrating Google Sheets → PostgreSQL

1. Implement `CustomerRepository` and `PayoutRepository` against PostgreSQL.
2. Wire them in `createApp()` instead of the Sheets adapters.
3. Keep `PayoutService`, `ConversationOrchestrator`, WhatsApp, and agent layers unchanged.
4. Replace sequential Sheets code generation with a DB sequence / transactional counter.
5. Backfill existing `PAY-*` rows if needed.

## Business flow summary

```text
Customer message
  → webhook extract sender + text
  → AI structured extraction (Zod-validated)
  → merge conversation state
  → backend validate customer/amount/duplicates
  → generate PAY-#####
  → append PayoutRequests row (status=Pending)
  → WhatsApp confirmation with request code
```
